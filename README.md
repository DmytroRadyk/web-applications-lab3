# Лабораторна робота №3 — «Спадщина: Замки України»

Тематичний Rails-сайт за [завданням](https://github.com/csn-classroom-26-27/web-applications-lab3). Публічний каталог замків, власні записи користувачів, реєстрація/вхід через Devise та Bootstrap 5 із Sass.

## Локальний запуск

Потрібен Ruby 3.3 і Bundler. На Windows використовуйте RubyInstaller з Devkit.

~~~sh
bundle install
bundle exec rails db:prepare
bundle exec rails db:seed
bundle exec rails server -p 3001
~~~

Відкрийте http://localhost:3001. Зареєструйте власний акаунт. Seed створює три демонстраційні замки; спільного відомого пароля для seed-користувача немає.

## Функції та права

- Перегляд каталогу й окремого замку доступний усім.
- Пошук за назвою/населеним пунктом і фільтр за областю; український пошук не залежить від регістру.
- Devise: реєстрація, вхід, вихід, запам’ятовування, відновлення пароля.
- Додавання доступне після входу. Редагування та видалення — лише автору; сервер повертає 403 при спробі змінити чужий запис.
- Переданий із форми `user_id` ігнорується: автор визначається з поточної сесії.
- Назва, область, населений пункт й опис обов’язкові; рік необов’язковий та має бути між 1 і поточним роком.
- CSRF-захист, хешування паролів BCrypt, безпечне відображення введеного тексту.
- Bootstrap підключений ґемом, стилі компілюються локально; зовнішній CDN не потрібний.

## Перевірка

~~~sh
bundle exec rails test
bundle exec rails zeitwerk:check
bundle exec rails assets:precompile
~~~

Локально: **12 тестів, 72 assertions, 0 failures/errors/skips**. Перевірено CRUD, права гостя/автора/іншого користувача, спробу підміни автора, український пошук, валідації, реєстрацію, вхід/вихід, неправильний пароль та лист відновлення. Автозавантаження й assets успішні; основні сторінки також перевірені в браузері. Шаблон GitHub Actions наведено в `docs/github-actions.example.yml`; він не активований.

## Деплой на Render

Підготовлені `render.yaml` та `bin/render-build.sh`. Вони описують PostgreSQL і Ruby web service на free-планах. У production використовується PostgreSQL, локально — SQLite.

1. У Render створіть Blueprint із цього репозиторію. Для приватного репозиторію надайте Render доступ лише до нього.
2. Перевірте free-плани для бази й застосунку. За умовою лабораторної **не вводьте платіжні дані**.
3. Blueprint передає `DATABASE_URL` і генерує `SECRET_KEY_BASE`. Секрети не зберігаються в Git; `config/master.key` і `.env` ігноруються.
4. Build: `bash bin/render-build.sh`. Start: `bundle exec puma -C config/puma.rb`. Health check: `/up`.
5. Після Live перевірте каталог, реєстрацію, вхід, додавання, редагування, видалення та захист чужих записів. Build автоматично додає три демонстраційні замки; повторний seed не дублює записи.

Для листів відновлення на реальному домені потрібно задати `MAILER_FROM`, `SMTP_ADDRESS`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`; хост береться з `RENDER_EXTERNAL_HOSTNAME` або `APP_HOST`. У development листи видно в `log/development.log`, у тестах використовується тестова доставка. Реальні SMTP-секрети в репозиторій не додавайте. Приклад назв змінних — `.env.example`.

Публічна URL-адреса з’явиться після авторизації Render та успішного деплою; сам файл Blueprint не означає, що сайт уже розгорнуто.
